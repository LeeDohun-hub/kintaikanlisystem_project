# 데이터 설계（勤怠管理システム）

본 문서는 현재 저장소 기준 **MySQL 스키마·JPA 엔티티**에 따른 데이터 모델을 정리합니다. 스키마의 기준은 `backend/src/main/resources/db/migration/V1__baseline.sql` 및 `com.kintai.entity` 패키지입니다.

---

## 1. 개요

| 항목 | 내용 |
|------|------|
| DBMS | MySQL（InnoDB, utf8mb4） |
| 스키마 관리 | Flyway（`classpath:db/migration`）+ Hibernate `ddl-auto=update`（엔티티 보조） |
| 문자셋 | utf8mb4 / utf8mb4_unicode_ci |

---

## 2. ER 개념도

```mermaid
erDiagram
    employee ||--o| employee_account : "1:1 (동일 PK)"
    employee ||--o{ work_time : "1:N"

    employee {
        BIGINT employee_id PK
        VARCHAR employee_code UK
        VARCHAR employee_name
        VARCHAR department
        DECIMAL hourly_cost
        TINYINT active_flag
        DATETIME created_at
        DATETIME updated_at
    }

    employee_account {
        BIGINT employee_id PK_FK
        VARCHAR password_hash
        VARCHAR role
    }

    work_time {
        BIGINT work_id PK
        BIGINT employee_id FK
        DATE work_date
        TIME start_time
        TIME end_time
        INT break_minutes
        INT work_minutes
        VARCHAR remarks
        DATETIME created_at
    }

    batch_import_history {
        BIGINT import_id PK
        VARCHAR file_name
        VARCHAR status
        VARCHAR error_message
        DATETIME imported_at
    }
```

`batch_import_history`는 애플리케이션 엔티티로 존재하며, **다른 테이블과 FK로 연결되지 않습니다**（取込ログ専用）.

## 3. 테이블 정의

### 3.1 `employee`（従業員マスタ）

| 컬럼 | 타입 | NULL | 제약 | 설명 |
|------|------|------|------|------|
| employee_id | BIGINT UNSIGNED | NO | PK, AUTO_INCREMENT | 내부 식별자 |
| employee_code | VARCHAR(20) | NO | UNIQUE | 로그인·표시용 사원 코드 |
| employee_name | VARCHAR(50) | NO | | 성명 |
| department | VARCHAR(50) | YES | | 부서 |
| hourly_cost | DECIMAL(8,2) | NO | | 시급（원 단위 비즈니스에 사용） |
| active_flag | TINYINT | NO | DEFAULT 1, INDEX | 1: 유효, 0: 무효 |
| created_at | DATETIME(3) | NO | | 생성 시각 |
| updated_at | DATETIME(3) | NO | ON UPDATE | 갱신 시각 |

**비고:** JPA `@PrePersist` / `@PreUpdate`에서 `active_flag` 기본값·시각을 보완합니다.

---

### 3.2 `employee_account`（ログインアカウント）

| 컬럼 | 타입 | NULL | 제약 | 설명 |
|------|------|------|------|------|
| employee_id | BIGINT UNSIGNED | NO | PK, FK → employee | `employee`와 1:1, 동일 PK |
| password_hash | VARCHAR(255) | NO | | BCrypt 등 해시 |
| role | VARCHAR(20) | NO | | `ADMIN` / `EMPLOYEE`（Java `Role` enum） |

**관계:** `employee` 삭제 시 **CASCADE**로 계정도 삭제됩니다.

---

### 3.3 `work_time`（勤務実績）

| 컬럼 | 타입 | NULL | 제약 | 설명 |
|------|------|------|------|------|
| work_id | BIGINT UNSIGNED | NO | PK, AUTO_INCREMENT | 근무 행 ID |
| employee_id | BIGINT UNSIGNED | NO | FK → employee, INDEX | 근무자 |
| work_date | DATE | NO | UNIQUE(employee_id, work_date) | **직원·일 단위 1건** |
| start_time | TIME | NO | | 출근 시각 |
| end_time | TIME | NO | | 퇴근 시각 |
| break_minutes | INT UNSIGNED | NO | | 휴게（분） |
| work_minutes | INT UNSIGNED | NO | | 실근무（분） |
| remarks | VARCHAR(500) | YES | | 비고 |
| created_at | DATETIME(3) | NO | | 생성 시각 |

**비고:** `work_minutes`는 서비스 계층에서 시작·종료·휴게로부터 산출·검증합니다. `updated_at`은 Flyway V1 DDL에는 없고, 엔티티에도 생성 시각만 자동 설정되는 형태입니다（변경 이력은 `created_at` 기준）.

---

### 3.4 `batch_import_history`（一括取込履歴）

| 컬럼 | 타입 | NULL | 설명 |
|------|------|------|------|
| import_id | BIGINT UNSIGNED, PK | NO | 이력 ID |
| file_name | VARCHAR(100) | NO | 파일명 |
| status | VARCHAR(20) | NO | 예: SUCCESS / ERROR |
| error_message | VARCHAR(255) | YES | 실패 시 메시지 |
| imported_at | DATETIME(3) | NO | 처리 시각 |

---

## 4. 식별자·참조 무결성

- **사원 코드** `employee_code`: 전역 유일（UK）.
- **근무**: `(employee_id, work_date)` 유일 → 동일 직원·동일 일자에 복수 행 불가.
- **계정**: `employee_id`가 `employee` PK와 1:1.

---

## 5. 애플리케이션 매핑

| 테이블 | JPA 엔티티 |
|--------|------------|
| employee | `Employee` |
| employee_account | `EmployeeAccount` |
| work_time | `WorkTime` |
| batch_import_history | `BatchImportHistory` |

`Role`은 DB의 `role` 문자열과 매핑되는 **enum**입니다.

---

## 6. 변경 시 유의사항

- DDL 변경 시 **Flyway 마이그레이션** 추가를 우선하고, `ddl-auto=update`에만 의존하지 않는 것이 운영에 유리합니다.
- 본 저장소의 `application.properties`에는 DB 접속 정보가 포함될 수 있으므로, **비밀번호·URL은 Git에 올리지 않고** `application-local.properties` 등으로 분리하는 것을 권장합니다.
