## 2. 要件範囲の要約（教育用要件定義書ベース）

- **従業員:** 勤務入力（日付・時間・休憩・区分・コメント・プロジェクト）、本人の勤務履歴照会  
- **管理者:** 全勤務照会、統計/集計、売上・損益（単価・月次）、キャッシュフロー（入金予定）  
- **技術スタック（案）:** バックエンド Java/Spring Boot、フロント React、DB MySQL、REST（JSON）、認証はセッション（将来 JWT 等を検討可）

## 4. データベース設計会議の議題（案）

1. **エンティティ一覧の確定**  
   - 予習スキーマを採用するか、テーブル分割/統合するか（例: 勤怠とプロジェクト割当、休暇/欠勤の区分）。  
2. **関係・制約**  
   - FK、ON DELETE 方針、`employee_code` vs 内部 `id` の利用範囲。  
3. **インデックス**  
   - 月次照会・従業員別照会パターンに合った複合インデックス。  
4. **コード/状態値**  
   - `work_type`, `payment_schedules.status` など ENUM vs コードテーブル vs VARCHAR。  
5. **シード・マイグレーション**  
   - `schema.sql` 一発 vs Flyway/Liquibase 導入の可否。  
6. **セキュリティ**  
   - パスワードはハッシュのみ保存、個人情報・マスキング方針（管理者画面）。

## 5. アプリケーション設計会議の議題（案）

1. **アーキテクチャ**

5. **非機能**  
   - 同時接続・セッションタイムアウト、ログ、デプロイ構成（静的ファイル + API サーバー）。
